# nersc-iri-client

A Python client for the NERSC IRI API ([`api.iri.nersc.gov`](https://api.iri.nersc.gov)).

The package is modelled on NERSC's Superfacility API client,
[`sfapi_client`](https://github.com/NERSC/sfapi_client), and applies its design
principles to the newer IRI API:

- **async / sync duality** — a single source of truth in `_async/` with `_sync/`
  generated by [`unasync`](https://github.com/python-trio/unasync)
- **pydantic models generated from the OpenAPI spec**
- **resource-based client** — compute/filesystem resources discovered and bound
  by id, name, or group
- **retry with tenacity** and **awaitable job and task objects**

## Installation

```shell
uv sync --extra dev
```

`uv` is the single source of truth for dependency resolution. To install just
the package (no dev/tooling extras):

```shell
uv pip install -e .
```

Requires Python 3.10+.

## Authentication

IRI uses a **static bearer token** — there is no OAuth/token endpoint. The
client resolves a token by priority:

1. the `access_token` constructor argument
2. the `IRI_API_TOKEN` environment variable
3. `~/.ssh/nersc-token`

```python
from iri_client import Client

# Explicit token
client = Client(access_token="...")

# Or rely on IRI_API_TOKEN / ~/.ssh/nersc-token
client = Client()
```

Resolution is **lazy**. Public read-only endpoints (facility, status, and
resource discovery) work with **no token at all**; a descriptive `AuthError` is
raised only when a privileged call (job submission, filesystem access, account
info) is attempted without credentials.

## Quickstart

```python
from iri_client import Client, ComputeResourceName, FilesystemResourceName

with Client() as client:
    # Bind the Perlmutter compute resource (an alias for the "jobs" group)
    perlmutter = client.compute(ComputeResourceName.perlmutter)

    # Submit a short job on the debug queue
    from iri_client._models import JobSpec
    job = perlmutter.submit(
        JobSpec(
            name="hello",
            executable="/bin/echo",
            arguments=["hello iri"],
            directory="/pscratch/sd/e/elvis/tmp",
            stdout_path="/pscratch/sd/e/elvis/tmp/hello.out",
            stderr_path="/pscratch/sd/e/elvis/tmp/hello.err",
            attributes={"queue_name": "debug", "account": "m3792", "duration": 60},
            resources={"node_count": 1, "processes_per_node": 1},
        )
    )

    # Block until it reaches a terminal state (up to 300s)
    job.wait(timeout=300)
    print(f"state: {job.status.state}, exit code: {job.status.exit_code}")

    # List files on the scratch filesystem resource
    fs = client.filesystem(FilesystemResourceName.scratch)
    for entry in fs.list("/pscratch/sd/e/elvis/tmp"):
        print(entry["name"], entry["type"], entry["size"])
```

## Async usage

The same API is available asynchronously via `AsyncClient`. The sync and async
classes expose identical method names (generated by `unasync`):

```python
import asyncio

from iri_client import AsyncClient, ComputeResourceName, FilesystemResourceName


async def main() -> None:
    async with AsyncClient() as client:
        perlmutter = client.compute(ComputeResourceName.perlmutter)
        job = await perlmutter.submit(spec)   # spec: JobSpec
        await job.wait(timeout=300)           # or: await job
        print(f"state: {job.status.state}")
        fs = client.filesystem(FilesystemResourceName.scratch)
        await fs.mkdir("/pscratch/sd/e/elvis/tmp/newdir")


asyncio.run(main())
```

In the async API a job is awaitable directly (`await job`), which blocks until
it reaches a terminal state.

## API overview

### Client

`client.compute(...)` and `client.filesystem(...)` discover and bind a resource
by **id, name, or group**. They accept an enum member or a plain string:

```python
compute = client.compute("jobs")                          # by group name
fs = client.filesystem("scratch")
fs_by_id = client.filesystem("43d8f6c0-...")              # by resource id
```

The well-known names are exposed as enums exported from the package root so
callers can avoid string literals:

- `ComputeResourceName` → `jobs`, `compute`, `perlmutter`
- `FilesystemResourceName` → `scratch`, `homes`, `common`, `cfs`, `dtns`,
  `jobs`, `compute`, `login`

`ComputeResourceName.perlmutter` is an **alias for the `jobs` group** (its
value is literally `"jobs"`), so it binds to the same resource the IRI
deployment expects job submission against.

Other read-only endpoints:

```python
client.account.projects()      # the projects you belong to
client.facility.info()         # facility metadata
client.facility.sites()
client.status.resources()      # resources + current status
client.status.statuses()       # "name -> status" map
client.status.events()
client.status.incidents()
```

### Compute

`Compute` (returned by `client.compute(...)`) manages jobs on a compute
resource:

- `submit(jobspec: JobSpec)` → `Job`
- `run(jobspec: JobSpec)` → submit and block until finished → `Job`
- `list(filters=None, historical=None, limit=None)` → `List[Job]`
- `job(jobid)` → `Job` handle

`Job`:

- `status` → `JobStatus` (`state`, `time`, `message`, `exit_code`, `meta_data`)
- `wait(timeout=None)` → bulk until completed / failed / canceled
- `cancel()`
- `await job` (async only) → block until finished

`JobStatus.state` is a `JobState` enum: `queued`, `held`, `active`,
`completed`, `failed`, `canceled` (note the **single-L** IRI spelling of
"canceled").

### Filesystem

IRI runs every filesystem operation through an **async task queue**: the
request returns a `Task` immediately and the result is fetched by polling
`GET /task/{task_id}` until it reaches a terminal state.

Two flavours of every operation:

- `submit_*` → returns the `Task` so you can poll, cancel, or batch
- blocking form → awaits the task and returns the result

Data-returning operations (unwrapped `result.output`): `list`, `stat`, `view`,
`head`, `tail`, `checksum`, `download`.

Mutating/void operations (return `None`): `mkdir`, `chmod`, `chown`, `copy`,
`move`, `symlink`, `rm`, `upload`, `compress`, `extract`.

```python
fs = client.filesystem(FilesystemResourceName.scratch)

entries = fs.list("/pscratch/sd/e/elvis/tmp")
stat = fs.stat("/pscratch/sd/e/elvis/tmp/input.dat")
contents = fs.tail("/pscratch/sd/e/elvis/tmp/out.err", lines=20)
fs.mkdir("/pscratch/sd/e/elvis/tmp/newdir", parent=True)
fs.copy("/pscratch/sd/e/elvis/tmp/a.dat", "/pscratch/sd/e/elvis/tmp/b.dat")
fs.upload("/home/elvis/local.dat", "/pscratch/sd/e/elvis/tmp/local.dat")

# The asynchronous flavour lets you enqueue and await later
task = fs.submit_mkdir("/pscratch/sd/e/elvis/tmp/newdir")
# ... do other work ...
task.wait()
```

Uploads are small files (see [CONVERSION.md](CONVERSION.md)); for larger
payloads copy them into the filesystem directly.

`fs.list(path)` returns a list of entry dicts with keys `name`, `type`,
`link_target`, `user`, `group`, `permissions`, `last_modified`, and `size`.

### Exceptions

- `IriError` — base error (renamed from `SfApiError`)
- `AuthError` — a privileged call was attempted without credentials
- `ResourceLookupError` — a resource id/name/group was not found (or ambiguous)
- `ClientKeyError` — a job/task/remote path key was not found

## Testing

The offline test suite is hermetic (no live network): it runs the token-free
public endpoints against `httpx.MockTransport` canned payloads.

```shell
uv run ruff check .                          # lint
uv run python -m pytest -m "not api_auth" -q  # offline tests
```
